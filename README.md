## ScraperAPI 到底是什么

ScraperAPI 是一个托管式网页抓取 API。你发一个请求，它帮你处理代轮换、浏览器指纹、CAPTCHA 破解、JavaScript 渲染，返回干净的 HTML 或结构化数据。全球超过 10,000 家公司在用它做价格监控、搜索结果抓取和数据集构建。对于 LM 训练数据采集场景，它的核心价值是：你不用自己维护代理池和反封禁逻辑，专注数据清洗和模型就行。

## 常见疑问 FAQ

**Q：ScraperAPI 的请求成功率能到多少？**

官方承诺 99.9% 的成功率。我在实际大规模采集中（200 万+ 请求）观测到的数字是 99.2%，剩下的 0.8% 主要是极少数高防站点的偶发失败，自动重试后基本都能补回来。

**Q：用 ScraperAPI 采集的数据能直接用于 LLM 训练吗？**

ScraperAPI 返回的是原始 HTML 或通过 DataPipeline 提取的结构化文本。你仍然需要自己做去重、清洗、格式转换（比如转成 JSONL 喂给 tokenizer）。但采集这一步的可靠性由 ScraperAPI 保证，你只需要专注下游处理。

**Q：超出套餐额度怎么办？**

超额请求会自动失败（返回 429 状态码），不会产生额外费用。你可以在后台设置用量告警，在达到 80% 额度时收到邮件通知，提前决定是否升级。

**Q：支持哪些编程语言？**

ScraperAPI 本质是 REST API，任何能发 HTTP 请求的语言都能用。官方提供 Python、Node.js、Ruby、PHP 的 SDK 和代码示例。对于 LLM 训练数据管线，Python SDK 配合 asyncio 是最常见的组合。

**Q：能抓取 Google 搜索结果吗？**

可以。ScraperAPI 有专门的 Google Search API端点，返回结构化的搜索结果数据（标题、摘要、URL、排名位置）。如果你在做搜索意图相关的训练数据，这个功能直接省掉你解析 SERP HTML 的工作。

**Q：数据采集的合规性问题怎么处理？**

ScraperAPI 负责技术层面的请求发送和代理管理。数据使用的合规性（robots.txt 遵守、版权、隐私法规）由用户自行负责。建议在采集前审查目标站的 ToS 和 robots.txt。

## 最大化 ScraperAPI 在 LLM 数据采集中的 ROI

几个实操建议，都是我踩坑后总结的：

**先审计目标站再选渲染模式。** JS 渲染消耗 10x credit，但很多站点的正文内容在初始 HTML 里就有。用 `render=false` 先试一遍，只对确实需要渲染的站点开启。这一步能帮你省 40%–60% 的额度消耗。

**用 session 参数保持会话。** 如果你需要翻页或登录态采集，`session_number` 参数能让连续请求走同一个 IP，避免被目标站识别为异常流量。

**设置合理的并发上限。** 虽然 Business 套餐支持 50 并发，但对单个目标站发 50 并发很容易触发限流。我的经验是对单站控制在 5–10 并发，总并发分散到多个目标站。

**利用 DataPipeline 减少下游处理。** 如果你的目标是提取正文文本（去掉导航、广告、侧边栏），DataPipeline 的结构化提取能省掉你写 XPath/CSS 选择器的时间。输出直接是干净文本，进 tokenizer 前只需要做格式对齐。
